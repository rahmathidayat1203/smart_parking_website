# Dokumen Kebutuhan Masa Depan (Future Roadmap & Requirements)
## Smart Parking Monitoring & RFID Member System

Dokumen ini mencatat seluruh arsitektur, fitur, kebutuhan teknis, serta peningkatan sistem yang diperlukan untuk pengembangan sistem Smart Parking di masa mendatang (Next Milestones & Future Roadmap).

---

## 1. Automatic License Plate Recognition (ALPR / ANPR) & Computer Vision
### Latar Belakang & Kebutuhan
Saat ini verifikasi gerbang hanya mengandalkan sensor ultrasonic $\le 20\text{ cm}$ dan kartu RFID. Untuk mencegah penyalahgunaan kartu (peminjaman kartu RFID ke kendaraan lain), diperlukan validasi plat nomor secara otomatis.

### Rencana Implementasi Teknis:
1. **Hardware Edge Camera**:
   - Integrasi kamera gerbang (ESP32-CAM atau IP Camera RTSP 1080p).
   - Pemicu pengambilan gambar (*trigger capture*) saat ultrasonic mendeteksi mobil berhenti $\le 20\text{ cm}$.
2. **AI / OCR Inference Pipeline**:
   - Model deteksi plat nomor: **YOLOv8-Nano** untuk lokalisasi plat kendaraan.
   - Model pengenalan karakter: **PaddleOCR** atau **CRNN** untuk membaca teks plat nomor Indonesia.
3. **Cross-Validation Logic**:
   - Sistem mencocokkan plat nomor hasil OCR dengan kolom `license_plate` pada tabel `parking_members` untuk `rfid_uid` yang dipindai.
   - Jika plat nomor berbeda, sistem memicu status peringatan `PLATE_MISMATCH` dan membunyikan alarm buzzer ganda, serta mengirim notifikasi ke dashboard admin.

## 2. Sistem Pembayaran Parkir & Tarif Otomatis (Payment Gateway & QRIS)
### Latar Belakang & Kebutuhan
Sistem saat ini dikhususkan bagi member terdaftar. Untuk kendaraan umum / non-member, dibutuhkan pencatatan sesi parkir berbayar dan pembayaran nirsentuh.

### Rencana Implementasi Teknis:
1. **Skema Database Sesi Parkir (`parking_sessions`)**:
   ```sql
   create table parking_sessions (
       id bigint generated by default as identity primary key,
       session_ticket_id text unique not null,
       vehicle_plate text,
       rfid_uid text,
       check_in_time timestamptz not null default now(),
       check_out_time timestamptz,
       duration_minutes integer,
       rate_per_hour numeric default 3000,
       total_amount numeric default 0,
       payment_method text check (payment_method in ('qris', 'e_wallet', 'member_balance', 'cash')),
       payment_status text default 'unpaid' check (payment_status in ('unpaid', 'paid', 'exempt')),
       created_at timestamptz default now()
   );
   ```
2. **Payment Gateway Integration**:
   - Integrasi API **Midtrans** / **Xendit** / **QRIS Dinamis**.
   - Saat kendaraan non-member ingin keluar di gerbang keluar, layar LCD/TFT menampilkan QRIS Dinamis sesuai durasi parkir aktual.
   - Webhook callback dari payment gateway otomatis membuka palang gerbang keluar ketika pembayaran berstatus `settlement`.
3. **Grace Period & Tarif Progresif**:
   - Gratis biaya parkir untuk *grace period* (misal: $\le 10\text{ menit}$).
   - Perhitungan tarif jam pertama + tarif progresif per jam berikutnya + denda tiket/kartu hilang.

## 3. Arsitektur Multi-Gerbang Terdistribusi (Dual-Gate & Scalable Zones)
### Latar Belakang & Kebutuhan
Mengembangkan sistem dari gerbang tunggal menjadi jaringan gerbang terdistribusi (Gate Masuk dan Gate Keluar terpisah, serta area parkir bertingkat/multi-zona).

### Rencana Implementasi Teknis:
1. **Node Topology**:
   - `GATE-IN-01` (ESP32-S3 Masuk): Ultrasonic masuk, RFID Reader masuk, Dispenser Tiket/Barcode non-member, Servo Gate Masuk.
   - `GATE-OUT-01` (ESP32-S3 Keluar): Ultrasonic keluar, RFID Reader keluar, Barcode scanner tiket, Layar QRIS tarif, Servo Gate Keluar.
   - `SLOT-ZONE-A`, `SLOT-ZONE-B` (ESP32 Node Slot): Node khusus pembacaan sensor IR multi-slot (8 hingga 16 slot per multiplexer PCA9548A / 74HC4067).
2. **Migrasi Protokol: HTTP Polling ke MQTT / WebSocket**:
   - Mengganti HTTP Polling berkala (2.5s) dengan **MQTT Broker (EMQX / Mosquitto)** via QoS 1 atau **Supabase Realtime WebSockets** (`broadcast` & `presence`).
   - Latensi transmisi status gerbang berkurang dari 1000–2500ms menjadi $< 100\text{ms}$.

## 4. Ketahanan Offline & Edge Caching (Offline Fallback Mode)
### Latar Belakang & Kebutuhan
Jika jaringan WiFi lokal terputus atau koneksi Supabase mengalami gangguan sementara, palang gerbang tidak boleh berhenti beroperasi total bagi member resmi.

### Rencana Implementasi Teknis:
1. **Penyimpanan Lokal ESP32 (LittleFS / NVS / EEPROM)**:
   - Sinkronisasi tabel `parking_members` aktif ke dalam file biner lokal pada flash memory ESP32 saat online (`whitelist_cache.json`).
   - Kapasitas cache lokal mampu menampung hingga 500 member aktif offline.
2. **Offline Transaction Buffer**:
   - Setiap scan kartu saat mode offline dicatat ke antrean flash buffer lokal.
   - Begitu koneksi internet pulih (`WiFi.status() == WL_CONNECTED`), ESP32 secara otomatis mengunggah (*flush batch*) seluruh log scan yang tertunda ke tabel `rfid_scans`.
3. **Hardware Watchdog Timer (WDT) & Power Backup Telemetry**:
   - Mengaktifkan Task Watchdog Timer (TWDT) FreeRTOS 5 detik untuk auto-reboot aman jika terjadi *deadlock* pada loop WiFi.
   - Sensor pemantau tegangan baterai cadangan (UPS 12V ke 5V stepdown) untuk notifikasi saat terjadi pemadaman listrik PLN.

## 5. Over-The-Air (OTA) Remote Firmware Update
### Latar Belakang & Kebutuhan
Memperbarui firmware ESP32 di lokasi tanpa perlu mencolokkan kabel USB ke komputer atau membongkar housing casing gerbang.

### Rencana Implementasi Teknis:
1. **Fitur Web OTA Streamlit**:
   - Menu upload file binary `.bin` hasil kompilasi Arduino / PlatformIO di halaman admin.
   - Penyimpanan file firmware di Supabase Storage bucket `firmware_updates`.
2. **ESP32 OTA Client**:
   - ESP32 mengecek versi firmware via REST endpoint `/rest/v1/iot_devices?select=target_firmware_version`.
   - Mengunduh dan mem-flash firmware via library `HTTPUpdate.h` dengan verifikasi hash SHA-256.

## 6. Smart Parking Guidance System (Indikator Visual LED & Layar VMS)
### Latar Belakang & Kebutuhan
Memandu pengemudi langsung ke slot yang tersedia di dalam area parkir luas tanpa harus berkeliling mencari slot kosong.

### Rencana Implementasi Teknis:
1. **Overhead RGB LED per Slot**:
   - Pemasangan LED WS2812B beralamat di atas tiap slot:
     - Hijau: Slot Kosong.
     - Merah: Slot Terisi.
     - Biru: Slot Khusus Disabilitas / VIP Member.
     - Kuning: Slot Terpesan (Booked/Reserved).
2. **Variable Message Sign (VMS Display)**:
   - Panel LED Matrix P10 atau LCD outdoor di pintu gerbang utama yang menampilkan:
     `LANTAI 1: KOSONG 5 SLOT | LANTAI 2: KOSONG 12 SLOT`.

## 7. Aplikasi Mobile Pengemudi & Integrasi NFC Smartphone
### Latar Belakang & Kebutuhan
Memberikan kenyamanan bagi pengemudi untuk memeriksa ketersediaan slot sebelum berangkat dan menggunakan smartphone sebagai kartu akses.

### Rencana Implementasi Teknis:
1. **Mobile App (Flutter / React Native)**:
   - Peta navigasi slot parkir real-time.
   - Riwayat parkir, saldo member, dan invoice digital.
   - Fitur *Reserve Slot* (reservasi slot parkir hingga 15 menit sebelum kedatangan).
2. **NFC Smartphone Access**:
   - Memanfaatkan fitur NFC pada smartphone (Android Host Card Emulation / Apple VAS) sehingga pengemudi cukup menempelkan HP ke reader gerbang tanpa perlu kartu fisik.

## 8. Anti-Passback Algorithm & Audit Trail Forensik
### Latar Belakang & Kebutuhan
Mencegah kecurangan satu kartu member dipakai untuk memasukkan lebih dari satu kendaraan secara bergantian.

### Rencana Implementasi Teknis:
1. **Status Posisi Kendaraan**:
   - Kolom status pada member: `inside_parking (true/false)`.
   - Kartu yang berstatus `inside_parking = true` akan ditolak di gerbang masuk dengan notifikasi `DENIED: KARTU SUDAH DI DALAM`.
   - Kartu hanya dapat masuk kembali setelah diverifikasi keluar di gerbang keluar (`inside_parking = false`).
2. **Audit Forensik Akses**:
   - Log komprehensif mencakup durasi buka gerbang, foto kendaraan saat masuk, dan peringatan deteksi ganjil (*tailgating* / mobil membuntuti tanpa tap).

## 9. Analytics, Occupancy Forecasting & Laporan Otomatis
### Latar Belakang & Kebutuhan
Menyediakan *business intelligence* bagi pengelola gedung untuk efisiensi tarif dan alokasi ruang.

### Rencana Implementasi Teknis:
1. **Model Machine Learning Forecasting**:
   - Prediksi jam sibuk (*peak hours*) menggunakan regresi deret waktu (ARIMA / Prophet).
   - Rekomendasi penyesuaian tarif dinamis pada waktu sibuk.
2. **Automated Export & Notification**:
   - Pengiriman rekapitulasi harian/bulanan via Telegram Bot / WhatsApp API.
   - Ekspor otomatis laporan PDF dan Excel berisi statistik utilisasi slot harian.
